What it is

A control panel that lives with the server.

Obsisphere serves its own web UI and JSON APIs from the Minecraft plugin process. It is designed for people who want a serious browser-based administration workspace without handing every staff member shell access or depending on an external SaaS dashboard.

One plugin. One panel. Most day-to-day server work.

Dashboard telemetry, file operations, player moderation, inventories, worlds, backups, plugins, scheduler, logs, audit trails, staff accounts, permissions, appearance controls and live tools sit under one permission-aware interface.

Technical architecture

A Minecraft plugin on one side. A real web application on the other.

Obsisphere is intentionally fairly boring in its core stack: Java on the server, an embedded HTTP layer, vanilla web technologies in the browser, database-backed logs, and specialized WebGL/worker code where the product actually needs it.

BrowserHTML · CSS · JavaScript · WebGL · IndexedDB
↕ HTTP / JSON / SSE
Obsisphere embedded panel serverStatic assets · API handlers · sessions · permissions
↕
PersistenceSQLite · YAML · JSON
Minecraft serverBukkit / Paper APIs

Backend

Java plugin code, embedded HTTP serving, bounded worker execution and Minecraft-thread handoff for server-affecting work.

Frontend

Vanilla HTML/CSS/JS with responsive layouts, themes, modals, toasts, dashboards and specialized live pages.

Map

WebGL terrain rendering, workers, chunk streaming, resource-pack-derived assets and persistent IndexedDB client caching.

Security

TOTP 2FA, PBKDF2 password hashing, CSRF checks, sessions, failed-auth controls and granular permission enforcement.

Persistence

Database-backed audit/activity history plus server configuration, policies, schedules and other durable panel state.

Build modes

AUTH_REQUIRED, DEV_NO_AUTH and DEV_NO_AUTH_LAN.
