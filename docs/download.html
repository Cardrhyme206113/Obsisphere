Recommended install flow

  1. Back up the server and plugin data.
  2. Place the Obsisphere JAR in the server plugins directory.
  3. Start the server and read the first-run bootstrap instructions.
  4. Create the master panel account.
  5. Set a strong password and register TOTP 2FA.
  6. Create roles before giving access to other staff.
  7. Test files, console, inventory and world actions on a staging server first.

Deployment notes

The panel is an administrative surface. Do not interpret “web UI” as “safe to expose blindly to the public internet.”
  • Use 2FA for important accounts.
  • Give users only the permissions they need.
  • Keep file/console/world permissions restricted.
  • Review audit history for sensitive changes.
  • Keep reliable external backups.
  • Understand your reverse proxy/TLS/network setup before public exposure.

Build modes

AUTH_REQUIRED is the normal authenticated build mode. DEV_NO_AUTH and DEV_NO_AUTH_LAN exist for development/testing workflows and should not be treated as equivalent production configurations.

AUTH_REQUIREDNormal account, session and permission flow.
DEV_NO_AUTHDevelopment convenience build.
DEV_NO_AUTH_LANNo-auth development flow intended around LAN testing.
